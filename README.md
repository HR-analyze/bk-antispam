# BK AntiSpam

Первый этап модератора комментариев Telegram-канала сети кулинарных лавок.

## Сейчас удаляется

- любая ссылка в сообщении;
- мат и распространённые завуалированные варианты;
- очевидные рекламные/спам-шаблоны;
- предложения заработка, вакансии и подработки с рекламным призывом,
  включая запросы вида «нужна девочка» во всех формах;
- порнография, интим-услуги, вебкам и «взрослый» контент;
- казино/ставки и похожий очевидный спам.

Обычные обращения клиентов, жалобы, вопросы про магазины, бонусы, приложение, продукты, мероприятия и сотрудников бот не трогает.

## Запуск

Переменные окружения — см. `.env.example`:

```text
BOT_TOKEN=...            # обязательно
CHAT_ID=-100...          # чат для модерации, опционально
DATABASE_URL=postgres... # логирование сообщений, опционально
DASHBOARD_API_KEY=...    # ключ HTTP-API, опционально
```

Только бот:

```bash
pip install -r requirements.txt
python bot.py
```

Бот вместе с HTTP-API (`api.py`) на порту `PORT`:

```bash
python main.py
```

Для Telegram бот должен быть администратором группы обсуждений с правом удаления сообщений. Telegram разрешает боту-администратору удалять сообщения других пользователей в группе/супергруппе; для супергруппы нужен `can_delete_messages`. 

## Какая версия правил реально запущена

Самая частая причина «починили, а не работает» — задеплоен старый образ.
Спроси бота:

```text
/version
```

Он ответит хешем и количеством правил. Хеш считается по исходникам
`moderation.py` и `bot.py` целиком, то есть меняется от любой правки —
и словарей, и самой логики. Чтобы сверить, посчитай ожидаемое значение
локально на том коммите, который деплоил:

```bash
python -c "from moderation import ruleset_fingerprint as f; print(f())"
```

Совпало — запущен именно этот код. Не совпало — деплой не доехал. Если бот
на команду не отвечает вовсе, значит запущен код старше этой версии.

Точную ревизию можно зашить в образ при сборке, тогда `/version` покажет и её:

```bash
docker compose build --build-arg BUILD_SHA=$(git rev-parse --short HEAD)
```

Без доступа к боту версию можно определить двумя сообщениями в чат:

| сообщение | старый код (до правок) | промежуточный | актуальный |
|---|---|---|---|
| `нужна девочка` | остаётся | удаляется | удаляется |
| `есть мандарины в наличии?` | удаляется | удаляется | остаётся |

Второе — не опечатка: раньше фильтр мата ловил корень `манд` и удалял
«мандарины». Если это сообщение удаляется — запущен код без этой починки.

Пересборка обязательна: `docker restart` поднимает **старый** образ.

```bash
git pull
docker compose up -d --build
```

## Если бот не удаляет то, что должен

Сначала проверь Telegram-сторону — правила модерации покрыты тестами, поэтому
причина почти всегда здесь:

```bash
python tools/diagnose.py
```

Скрипт только читает и проверяет: жив ли токен, не перехватывает ли апдейты
вебхук, существует ли чат из `CHAT_ID`, не указывает ли `CHAT_ID` на канал
вместо группы обсуждений, админ ли бот и выдано ли ему `can_delete_messages`.
В конце печатает, что именно исправить, и как читать логи.

Частые причины, по убыванию:

1. `CHAT_ID` — это id канала, а комментарии живут в связанной группе обсуждений;
2. бот не администратор группы либо без права «Удаление сообщений»;
3. контейнер не пересобран — работает старый образ (`docker compose up -d --build`, не `restart`);
4. установлен вебхук, из-за чего long polling не получает апдейты;
5. автор сообщения сам администратор — таких бот удалять не может в принципе.

## Тесты

Правила модерации покрыты тестами: что обязано удаляться и, что важнее, что
обязано остаться в чате. Перед каждой правкой словарей прогоняй их — иначе
легко начать удалять обычных клиентов.

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

Вся логика решения живёт в `moderation.py`: `classify_message(text, has_link)`
возвращает ключ из `REASONS` или `None`. `bot.py` только зовёт её и удаляет
сообщение — новые правила добавляй в `moderation.py` и сразу кейс в
`tests/test_moderation.py`.

## Дашборд

`dashboard/` — отдельное веб-приложение: количество сообщений, разбивка по
классификации, динамика по дням и раскрытие любого сообщения с детализацией.
Ставится независимо от бота (на свою ВМ), работает с БД только на чтение.

Подключается либо напрямую к PostgreSQL, либо к API бота из `api.py`.
Установка, переменные окружения и диагностика — в [dashboard/README.md](dashboard/README.md).
